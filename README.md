# FOS Campaign Tracker

Internal tool for tracking sponsored campaign performance across paid social, longform content, and cutdowns.

## What this is

**Hybrid architecture** — two surfaces, one data model:

- **`viewer/`** — the polished read-only Pulse dashboard. React + static HTML, designed in Claude Design. What AM, Sales, and Partnership Marketing see.
- **`app/`** — the Streamlit admin tool. Where Content Strategy uploads CSVs, manages campaigns, and triggers refreshes. Coming in v0.7+.

For v0.5, the pipeline is local-script-driven:

```
CSV exports                    → app/parsers/      → NormalizedPost list
       │
       ▼
config/campaigns.yaml          ← user config: goals, dates, post groups
       │
       ▼
app/compute/rollup.py          → cross-campaign rollups, top posts, channels
       │
       ▼
app/viewer/render.py           → viewer/data.js
       │
       ▼
Pulse dashboard renders        ← open viewer/index.html in a browser
```

## Quickstart

```bash
# Set up Python env (Python 3.12)
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"

# Run the parser tests against real sample exports
.venv/bin/pytest

# Refresh the viewer with real data from tests/fixtures + campaigns.yaml
.venv/bin/python -m app.viewer.refresh

# Open the dashboard
open viewer/index.html
```

## Repo layout

```
app/
  parsers/          # CSV → NormalizedPost (MS, Google Ads)
  compute/          # rollups, status pills, top posts
  viewer/           # data contract, render, refresh CLI
  components/       # Pulse-aligned Streamlit CSS for the admin app
  pages/            # Streamlit multi-page routes (TBD)
  main.py           # Streamlit admin entry
viewer/             # Pulse static React dashboard
  index.html        # entry — loads data.js
  styles.css        # design system
  data.sample.js    # canonical sample data showing required shape
  data.js           # generated by refresh.py — gitignored
  *.jsx             # React components
config/
  campaigns.yaml    # campaign metadata, goals, source file mappings
tests/
  test_parsers/     # parser tests against real fixtures
  fixtures/         # sample exports (redacted real data)
```
